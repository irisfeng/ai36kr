# 事故复盘：空首页（2026-08-01）

## 现象

首页整页空白：信息流显示"没有找到相关内容"，侧栏快讯/热榜/新品榜全空，脉搏条显示"今日 +0 · 0/33 源在线"。数据库本身无恙（Turso 当时有 845 篇文章）。

## 原因链（两个决策的交叉事故）

1. **历史决策 A**：为避免 Vercel 构建超时（当时 page data collection 跑 442 行水合 + DDL 花了 60s+），让构建期一律使用**空的 scratch 临时库**，不连 Turso。当时的页面全部 `force-dynamic`，构建期不需要数据，这个决策当时是对的。
2. **新决策 B（P0-1 优化）**：首页改为**静态壳 + ISR 300s 边缘缓存**，追求"大多数请求不触发 Function"。
3. **交叉点**：Next 在**构建期预渲染**静态首页 → 查询打到空 scratch 库 → 产出"空首页"HTML → 作为 PRERENDER 产物缓存到 Vercel 边缘 → 所有访客在 revalidate 周期内看到的都是空壳。
4. **自愈**：ISR 300s 到期后边缘重算，这次由运行中的 lambda（连着 Turso）产出正常首页，所以事故每次部署后只显示约 5 分钟——但每次部署都会复发。

## 为什么没被拦住

- 当时 smoke 只查 HTTP 200。空壳页面也是 200。
- 本地验证时本地库有数据，预渲染正常；问题只在 Vercel 构建环境（scratch）出现。

## 修复（已上线）

- `lib/db.js`：构建期**配置了 Turso 就直连远端**（845 行时水合/DDL 全部秒级跳过，无超时风险）；只有未配 Turso 时才退化 scratch。
- 构建期空库预渲染的姊妹问题（sitemap 同样只剩 6 个静态页）已于同日前修复（改 force-dynamic）。

## 防复发措施

1. **smoke 内容断言**（scripts/smoke.mjs）：除 HTTP 200 外，断言"首页含 post-card""首页不含空结果占位""脉搏有在线源"——空壳上线即报警。
2. **规则**：任何可静态化的页面，其构建期数据源必须与生产一致；引入"构建期用临时库"类优化时，必须复查所有静态产物。
3. **备份体系**（本目录的姊妹措施）：每日全量 JSONL 备份（10 表）→ snapshot 分支，14 份滚动保留；`scripts/restore-backup.mjs` 可幂等恢复，已通过恢复演练（行数全一致）。

## 时间线

- 10:19 P0-1 静态首页上线 → 边缘缓存空壳
- ~10:25 用户截图反馈"全空了"
- ~10:30 确认为构建期空库预渲染（此前一天同根因已命中 sitemap，未举一反三）
- ~10:40 修复上线（构建期配 Turso 直连）
- ~10:45 验证：PRERENDER 首页内容正常

## 教训

**同一个根因（构建期空 scratch 库）连续咬了两次（sitemap、首页）**。第一次修 sitemap 时只修了点，没有排查"构建期数据来源"这个面。教训：修 bug 时多问一句"同一机制还影响谁"。
